01Stack & approach

The mockups are intentionally static and JS-light to honor the brief's "avoid heavy client-side JavaScript / fast first paint" goal. Recommended build:

  • Any static-site generator (Astro, Eleventy, Hugo, Zola). Content as Markdown/MDX → the templates here.
  • One stylesheet: assets/quine.css already bundles the QUINE tokens (@import of tokens/*.css) plus the component classes. Link it once per page.
  • ~30 lines of JS total (assets/site.js): theme persistence only. The mobile nav is a pure-CSS checkbox toggle and needs no JS. Everything degrades gracefully without scripts.
  • Fonts: loaded from Google Fonts CDN via tokens/fonts.css. For production, self-host the four OFL families and swap the @import for local @font-face.

02Design-system usage

Use the QUINE classes directly — do not restyle. The vocabulary in play:

  • Buttons: .q-btn + .q-btn--primary|secondary|ghost + size --lg|--sm. Exactly one primary per view.
  • Cards: .q-card, with --marked (2px ember top-rule = "active/featured"), --grid (blueprint background), --interactive/--glow (hover).
  • Badges: .q-badge--alive (active/live, phosphor) · --ember (status/version) · --neutral (shipped) · --warning (archived) · --symbol (Wasm/Web3).
  • Eyebrows: the // comment prefix (.eyebrow / .comment) is the connective tissue. Use lowercase.
  • Iconography: math/logic Unicode glyphs (∴ ∀ λ ⊢ ⇄ ∇ ≡) in mono are the primary icon language; Lucide line-icons for conventional UI affordances. No emoji.
  • Voice: dry, precise, quietly hopeful. Numbers are heroes (38ms, 5/5 ack, 12kB). The Camus register ("one must imagine the cluster happy") used once per surface.

06Responsive & accessibility

Breakpoints

  • Nav: collapses to the CSS checkbox drawer at ≤ 860px.
  • Project grid: 3-up → 2-up → 1-up. Set in .proj-grid media queries (1-col at ≤ 760px).
  • Reading layout: capped at --read-max: 720px; the post-item date column stacks below 640px; hero h1 steps down at 900px / 640px.
  • Footer: 3-col → 2-col at 720px with brand spanning full width.

Accessibility (WCAG AA)

  • Skip-link, semantic landmarks (header/main/footer/nav), and aria-current / aria-label throughout.
  • Focus is the 2px offset ember ring (--ring) from the DS — keep it; don't remove outlines.
  • All .img-slots carry a role="img" + label; replace with real alt text — alt is a required slot.
  • Mixed-script paragraphs use lang attributes; Tamil gets extra line-height via :lang(ta).
  • Motion (cursor blink, tab underline) collapses under prefers-reduced-motion via the DS motion tokens.

07Per-template build prompts

Drop-in prompts to generate the remaining templates in the same system. Each assumes quine.css + the shared header/footer are already linked.

Books

Build books.html using quine.css and the shared header/footer. Two sections with .sec-head eyebrows "// writing" and "// reviews & reading". Section 1: authored books in a .book-grid of .book-card (cover img, .q-badge--ember status, title, blurb, "Read a chapter" .q-btn). Section 2: reviewed books — same .book-card but show author + an optional rating marker (★ in mono) and a "Read review" link to single-book.html. Use covers from assets/covers/. Voice: dry, precise.

Musings index + tag archive

Build musings.html: a .post-list of .post-item (date column, title link to single-musing.html, tag pills, excerpt, reading time). Allow one .post-item--pinned at top. Add an RSS affordance in the .sec-head ("// musings" + "Subscribe · RSS"). Add pagination at the bottom: mono page numbers with the current one in ember, prev/next .q-btn--ghost. tag-archive.html is the same list scoped to one tag, with an <h1> "#tag-name" and a post count below it, plus a breadcrumb.

About

Build about.html: a two-column intro (portrait .img-slot + bio in .prose), then a "// philosophy" section for the Optimistic-Nihilist worldview as a serif pull-quote + prose, then an experience timeline (vertical list: role, org, dates, one-line desc — use a 2px ember left-rule per entry), then grouped skill/domain pills, then interests + languages, then a CTA to Contact with an optional résumé link.

Contact (with form states)

Build contact.html: email dhilipsiva@pm.me shown large in mono with a copy button, the full .social-row, location "Bangalore, India" + an availability note slot, then a contact form using .q-field/.q-input (name, email, textarea message) with a primary submit. Design three states inline as labeled frames: default, error (use .q-input--error + .q-field__hint--error), and success (a .q-callout--ok "Sent. I'll reply when the quorum settles."). Note for build: wire to mailto or a form service.
